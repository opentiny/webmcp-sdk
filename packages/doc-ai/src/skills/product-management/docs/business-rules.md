# 业务规则说明

## 商品管理业务规则

### 1. 商品状态管理

#### 1.1 状态定义
- **上架 (on)**: 商品对用户可见，可正常销售
- **下架 (off)**: 商品对用户不可见，不可销售

#### 1.2 状态转换规则
```
新建商品 → 上架 (默认)
上架 ←→ 下架 (可互相转换)
任何状态 → 删除 (不可恢复)
```

#### 1.3 状态约束
- 新增商品默认为"上架"状态
- 下架商品不影响库存数量
- 删除商品将永久移除所有数据

---

### 2. 库存管理规则

#### 2.1 库存定义
- **正常库存**: 库存 >= 10
- **低库存**: 库存 < 10 且 > 0
- **无库存**: 库存 = 0

#### 2.2 库存约束
- ✅ 库存必须为非负整数 (>= 0)
- ✅ 库存为 0 时商品仍可保持"上架"状态
- ⚠️ 低库存商品建议及时补货
- ⚠️ 无库存商品建议下架或标记预售

#### 2.3 库存调整规则
- 库存增加：通过 `batch_adjust_stock` (adjustType='add', adjustValue > 0)
- 库存减少：通过 `batch_adjust_stock` (adjustType='add', adjustValue < 0)
- 库存设置：通过 `batch_adjust_stock` (adjustType='set')
- 调整后库存不能为负数

---

### 3. 价格管理规则

#### 3.1 价格约束
- ✅ 价格必须为正数 (> 0)
- ✅ 最低价格：¥0.01
- ✅ 价格精度：保留两位小数
- ⚠️ 建议价格范围：¥1 - ¥99,999

#### 3.2 价格调整规则

**百分比调整 (adjustType='percent')**:
```
新价格 = 原价格 × (1 + adjustValue)

示例：
原价 ¥1000，降价 10% (adjustValue = -0.1)
新价格 = 1000 × (1 - 0.1) = ¥900

原价 ¥1000，涨价 20% (adjustValue = 0.2)
新价格 = 1000 × (1 + 0.2) = ¥1200
```

**固定金额调整 (adjustType='fixed')**:
```
新价格 = 原价格 + adjustValue

示例：
原价 ¥1000，降价 ¥100 (adjustValue = -100)
新价格 = 1000 - 100 = ¥900

原价 ¥1000，涨价 ¥200 (adjustValue = 200)
新价格 = 1000 + 200 = ¥1200
```

#### 3.3 价格调整限制
- 调整后价格必须 >= ¥0.01
- 建议百分比调整范围：-50% 到 +100%
- 大幅度调价建议分步进行

---

### 4. 商品分类规则

#### 4.1 预定义分类
```typescript
enum Category {
  phones = '手机',      // 智能手机、功能机等
  laptops = '笔记本',   // 笔记本电脑
  tablets = '平板'      // 平板电脑
}
```

#### 4.2 分类约束
- ✅ 商品必须属于一个分类
- ❌ 不支持自定义分类（未来版本可能开放）
- ❌ 一个商品只能属于一个分类

#### 4.3 分类特殊规则
- 不同分类的商品可以同名
- 分类用于筛选和统计
- 分类可以在商品创建后修改

---

### 5. 批量操作规则

#### 5.1 批量操作限制
- 单次最多操作 100 个商品
- 超过限制需分批处理
- 建议每批 20-50 个商品以获得最佳性能

#### 5.2 批量操作失败处理
- **部分失败策略**: 成功的商品会被更新，失败的商品保持不变
- 返回详细的失败原因和成功/失败统计
- 建议检查失败项并单独处理

#### 5.3 批量操作最佳实践
```javascript
// ✅ 推荐：先查询后操作
const { products } = await query_products({ category: 'phones' })
const ids = products.map(p => p.id)
await batch_update_status({ ids, status: 'off' })

// ❌ 不推荐：盲目批量操作
await batch_update_status({ ids: ['1', '2', '...', '100'], status: 'off' })
```

---

### 6. 数据验证规则

#### 6.1 商品名称
- ✅ 不能为空字符串
- ✅ 长度：1-100 个字符
- ⚠️ 建议清晰描述商品特征

#### 6.2 商品描述
- ✅ 可选字段
- ✅ 长度：0-500 个字符
- ⚠️ 建议包含关键卖点

#### 6.3 商品图片
- ✅ 可选字段
- ✅ 必须是有效的 URL
- ⚠️ 建议使用 CDN 加速

---

### 7. 删除操作规则

#### 7.1 删除前检查
- 建议向用户展示商品信息
- 要求用户明确确认
- 提示删除后不可恢复

#### 7.2 删除约束
- ✅ 任何状态的商品都可以删除
- ❌ 删除操作不可撤销
- ⚠️ 建议实现"软删除"（标记为已删除而非真正删除）

#### 7.3 删除影响
- 商品数据永久移除
- 相关统计数据会更新
- 已删除的商品ID不会被重复使用

---

### 8. 权限管理规则

#### 8.1 操作权限（未来版本）
| 操作 | 所需权限 |
|------|---------|
| 查询商品 | `read:products` |
| 添加商品 | `create:products` |
| 编辑商品 | `update:products` |
| 删除商品 | `delete:products` |
| 批量操作 | `batch:products` |

#### 8.2 当前版本
- 所有操作无权限限制
- 建议在实际应用中添加权限控制

---

### 9. 数据一致性规则

#### 9.1 事务处理
- 批量操作使用事务保证一致性
- 单个商品操作失败不影响其他商品
- 返回详细的操作结果

#### 9.2 并发控制
- 支持多用户同时操作
- 后提交的修改会覆盖先提交的修改
- 建议实现乐观锁（未来版本）

---

### 10. 业务建议

#### 10.1 商品上架建议
- ✅ 确保商品信息完整
- ✅ 价格合理，符合市场行情
- ✅ 库存充足，避免缺货
- ✅ 图片清晰，描述准确

#### 10.2 库存管理建议
- 定期检查低库存商品
- 及时补货，避免断货
- 库存为 0 时考虑下架或预售
- 滞销商品考虑降价促销

#### 10.3 价格管理建议
- 定期分析价格竞争力
- 促销活动使用批量调价
- 避免频繁大幅度调价
- 保持价格稳定性

#### 10.4 数据分析建议
- 定期查看库存报告
- 分析各分类商品表现
- 识别畅销和滞销商品
- 基于数据优化运营策略
